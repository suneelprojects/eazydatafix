# Agentic EDA Deterministic Reporting

## Purpose

The reporting layer converts an existing `AgenticEDAResult` into reproducible,
human-readable artifacts without rerunning the Agentic EDA workflow:

```text
AgenticEDAResult
  -> AgenticEDAReportExporter
       -> ChartRegistry and chart handlers
       -> HTML renderer
       -> JSON renderer
       -> Markdown renderer
  -> AgenticEDAReportResult
```

The public façade is:

```python
edf.export_agentic_eda_report(
    workflow,
    dataset=None,
    output_dir="eazydatafix-report",
    formats=None,
)
```

HTML and JSON are generated by default. Markdown is opt-in.

## Separation of Responsibilities

- `AgenticEDAReportExporter` validates inputs, creates the dedicated output
  directory, coordinates charts and renderers, isolates partial failures, and
  returns artifact metadata.
- Text renderers own only their format. They receive the same immutable render
  context and preserve canonical report-section ordering.
- `ChartRegistry` routes only the visualisation recommendations already present
  in the workflow.
- Each chart handler owns one recommendation type and writes one PNG.
- Shared EDA validation verifies an optional dataset against workflow shape,
  columns, missingness, duplicates, and unique-value counts.
- `AgenticEDAReportResult` records generated files, generated and skipped
  visualisations, warnings, summary, and status.

## Honest Chart Generation

Structured execution output is sufficient for:

- Missing-value bar charts
- Categorical bar charts
- Boolean distribution charts
- Class distribution charts when a full categorical or boolean distribution is
  available
- Correlation heatmaps
- Datetime frequency charts

Histograms and box plots require raw observations. They are generated only when
the caller supplies a matching dataset. Without it, the recommendation remains
visible as a skipped chart with an explicit reason. No raw values are inferred
from quartiles or other aggregates.

## Artifact Safety and Determinism

- All library-controlled paths are resolved and checked against the requested
  output directory before writing.
- The current working directory and filesystem root are rejected as report
  output targets.
- Report text is written through a temporary file and atomically replaced.
- Matplotlib uses a non-interactive backend, saves PNG files, and closes every
  figure.
- Chart filenames contain a stable recommendation index, chart type, and target
  columns.
- Existing known artifact files are overwritten; unrelated files are retained.
- HTML escapes dataset-controlled content and references images with relative
  paths.
- JSON uses stable key ordering and indentation and includes workflow,
  artifact, and reproducibility metadata.

## Output Structure

```text
eazydatafix-report/
├── agentic-eda-report.html
├── agentic-eda-report.json
├── agentic-eda-report.md
└── visualisations/
    ├── 01-missing-value-chart-phone-salary.png
    ├── 02-bar-chart-department.png
    └── 03-time-series-line-chart-joining-date.png
```

The Markdown file appears only when requested. Artifact metadata lists only
successfully generated orchestrator recommendations.

## Failure Model

Unavailable honest source data produces a skipped visualisation, not a failure.
Unexpected chart or renderer exceptions are isolated and recorded as warnings.
The report status is:

- `success` when no renderer or chart fails
- `partial_failure` when some report artifacts succeed
- `failure` when no requested report file can be produced

The workflow and caller-owned DataFrame are never mutated.
